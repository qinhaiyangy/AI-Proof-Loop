# ProofLoop v0.1.0

定位：AI 编程任务的本地验收与人工返工工具。沿用现有正式仓库，不迁移旧目录，不把本版包装成独立自动编程 Agent 或通用 Harness。

## 本版范围

- 手工 JSON 验收契约：任务、要求对应关系、显式文件清单、命令和通过退出码。
- Node.js 真实进程检查：分离程序与参数，记录输出、退出状态、时间与超时情况。
- 每次独立证据：文件内容和 SHA-256、原契约、Markdown/JSON 报告及原始日志。
- 非通过时生成 `repair-prompt.md`，由用户交给 Codex 返工，再创建新记录复验。
- 契约和验收脚本改变需要新版本与用户确认，不能伪装成相同标准下的改进。

入口是 `src/acceptance/cli.mjs`。公开版保留原有设计测试及必要 JSON 夹具，明确区分抽象设计测试与真实运行验证。完整历史领域设计、Recorded/React 路线及其它前端草案留在本地，不进入本次精选发布。

开发方式：qinhaiyangy 负责产品方向、范围和验收约束，监督 Codex 实现与验证；Codex 承担具体编码、测试执行、示例修复和材料整理。首次公开提交是精选发布快照，不代表从零逐步手写的开发历史。原开发目录及其 Git 历史保持原样，私人记录不随发布上传。

## 最短演示

从仓库根目录运行：

```powershell
node scripts/demo-acceptance.mjs
```

这是使用固定错误/正确实现的确定性流程演示，检查进程真实执行，但没有实时模型自主修复。每次建立新的 `.proofloop/demo-*` 目录，打印失败和通过证据位置。

本轮 Codex 人工修改源码的实际运行证据保存在 [acceptance-v0.1 证据目录](../evidence/acceptance-v0.1/)，包含失败、修复后通过及对应代码差异；不把旧日志当成本次新代码的结果。

## 复验

```powershell
node src/acceptance/cli.mjs verify examples/keyword-filter/contract.json
node --test --test-timeout=30000 design-tests/*.test.mjs
node --test --test-timeout=30000 runtime-tests/*.test.mjs
```

运行事实以本次输出及保存的报告为准。此说明不承诺性能提升、模型任务成功率或任意仓库适用性。

### 本轮实际验证（2026-09-08，Windows，Node v24.19.0）

- 原有设计契约测试：18 通过、0 失败、0 跳过；两份测试及两份输入 JSON 的内容哈希与开工基线一致。
- 本轮运行层测试：47 项，46 通过、0 失败、1 跳过；包括真实进程、CLI、文件变动、证据缺失、原始字节、标准版本、任务历史、超时清理与一键演示。
- 跳过项：POSIX signal 元数据；Windows 不提供该测试需要的等价信号信息。脚本 SIGINT 事件测试验证了实际取消链路，但不冒充 Windows OS 级按键/信号投递测试。
- 真实人工返工示例：先 FAILED，再只修改源码后 PASSED。两次契约、验收脚本和运行层标识一致，代码标识不同；原始失败记录未覆盖。
- 公开派生证据：manifest 中 33 个 artifact 的哈希和长度核对通过；12 份公开日志分别记录原始与导出哈希。本机原始记录保持不变。
- 本轮没有模型 API 调用、依赖安装、GPU 环境修改或云端费用。

上述数量是测试执行结果，不是模型任务成功率。非 Windows 进程组清理尚未在本机验证。

## 已知边界与发布前检查

本版没有自动调用模型、自动修复或中断恢复。每次一个新的 Run/Attempt；历史关联不等于恢复。文件清单需要用户明确列出，不能自动覆盖间接依赖、系统环境和外部服务。通过仅表示约定检查通过，Proof 是验收证据，不是数学正确性证明。

检查命令必须可信；普通工作目录不是沙箱。超时会有界停止等待并尝试清理本次进程树，但无法保证脱离树的后代已退出。哈希用于识别版本，不用于宣传防篡改或可信执行。

维护者已确认公开发布至 `qinhaiyangy/AI-Proof-Loop`，采用 MIT 许可证。发布范围是经过审查的 CLI 文件集，不携带原开发分支历史、`.workbench` 私人记录、环境配置、密钥或未审查的 `.proofloop` 内容。已有本机记录及开发历史保留在本地。发布前扫描未发现候选文件中的明显密钥或私人路径；这不是无敏感信息的绝对保证。
